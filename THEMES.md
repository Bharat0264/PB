# PrintBee Theme Engine

A theme is a complete visual identity, not just light or dark. The engine lets the customer preview, apply and
keep a theme without reloading, and lets developers add a theme without touching existing pages.

Scope: the customer-facing pages (Home, Upload, Cart, Orders, Profile, Address, Help, Pricing, Terms, Change theme).
The warehouse, delivery and admin portals keep their own Sun Hive / Moon Hive styling for now.

## How it fits together

| File | Job |
| --- | --- |
| `theme-registry.js` | The list of themes. One object per theme. **The only file you edit to add a theme.** |
| `theme-engine.js` | The provider. Validates and registers themes, writes their tokens, applies one to `<html data-pb-theme="id">`, remembers the choice, previews and cancels. Loaded in `<head>` so there is no flash. |
| `theme-engine.css` | The semantic tokens (`--pb-*`) and the bridge from those tokens to the variables the existing stylesheets use. |
| `theme-adapter.css` | Generated by `tools/build_theme_adapter.py`. Makes the existing components follow any theme. Do not edit by hand. |
| `themes.html`, `themes.js`, `themes.css` | The Change theme gallery (`/themes`), reached from Profile > Appearance. |
| `/themes/<id>.css` | Optional extra CSS for a theme, loaded only while it is active. |
| `/themes/<id>.js` | Optional effects for a theme (animation, particles). Registers `window.PrintBeeThemeEffects[id] = {start(), stop()}`; the engine starts it while the theme is current and stops it when another theme takes over. |

Mode: Sun Hive / Moon Hive (`data-theme` = `light` / `dark`) still works exactly as before and is independent of the
theme. A theme says which modes it supports. A theme with a single mode locks the page to it and hides the Sun/Moon
switch; switching to a theme that supports both restores the customer's own choice.

Persistence: new and guest visits start with PrintBee in light mode. Guest choices use sessionStorage
(`printbee-theme-guest` and `printbee-admin-theme-guest`) while browsing. Continue as guest and sign-out reset
them. After `/api/auth/session` identifies a signed-in customer, choices are read from that account's
localStorage keys (`printbee-theme:<encoded email>` and `printbee-admin-theme:<encoded email>`). Unscoped
legacy choices are ignored because their owner is unknown. Theme and mode remain browser-local, and signed-in
choices sync between tabs for the same account. Unknown theme IDs fall back to PrintBee. Preview does not save.


## Add a new theme

1. Open `theme-registry.js` and add an object to the `push(...)` call:

```js
{
  id: 'wildfire',                       // kebab-case, unique
  name: 'Wildfire',
  tagline: 'Short line',
  description: 'One or two sentences for the gallery card.',
  modes: ['dark'],                      // 'light', 'dark' or both
  preview: {dark: {page: '#120b08', surface: '#1f130d', ink: '#fff1e6', accent: '#ff6a1f'}},  // gallery thumbnail
  tokens: {
    dark: {                             // one set per supported mode; every token below is required
      page: '#120b08', surface: '#1f130d', 'surface-2': '#2a1a12',
      ink: '#fff1e6', muted: '#d1ad98', border: '#3a2418',
      accent: '#ff6a1f', 'accent-strong': '#ff9a5c', 'accent-ink': '#1a0a02',
      success: '#5fd08a', warning: '#ffb84d', danger: '#ff6b6b', info: '#6fb1ff',
      'radius-card': '14px', 'radius-control': '10px', 'radius-pill': '10px',
      'shadow-raised': '0 8px 22px rgb(0 0 0 / .45)',
      'shadow-inset': 'inset 0 1px 3px rgb(0 0 0 / .5)',
      'shadow-pressed': 'inset 0 2px 6px rgb(0 0 0 / .55)',
      'font-body': 'Manrope, system-ui, sans-serif', 'font-display': 'Manrope, system-ui, sans-serif',
    },
  },
  stylesheet: '/themes/wildfire.css?v=1',   // optional (add ?v=2 when you change the file)
  script: '/themes/wildfire.js?v=1',        // optional effects, see below
  palette: ['#120b08', '#ff6a1f'],          // optional: colour dots on the gallery card (up to 10)
  // preview.dark.art (a CSS background) and preview.dark.nav give the gallery thumbnail its artwork
}
```

2. If you set `stylesheet`, create `themes/wildfire.css`. Scope everything under `:root[data-pb-theme="wildfire"]`.
   Use it for what tokens cannot express: textures, gradients, illustrations, extra fonts (`@font-face`).
   The server serves `/themes/<name>.css|js|woff2` already.
3. Run `python -m unittest test_themes` to validate the definition. The engine also logs a clear console error and
   refuses to register an invalid theme, so a bad theme can never break a page.
4. Open `/themes`. The new card appears with Preview and Apply. Nothing else needs registering.

## Wildfire (theme 01)

The first real theme, and the pattern for the next ones. It is dark only (the Sun/Moon switch is hidden while it is
active). `tokens` carry the palette, radii, shadows and fonts, so every component that follows the bridge picks them up.
`themes/wildfire.css` adds what tokens cannot: the forest and ember atmosphere on fixed layers behind the page,
film grain, a pine treeline, gold-hairline cards with a soft top sheen, a forest-green nav bar, ember buttons, themed
dialogs and focus rings, and an ember pulse on empty states. Every rule is scoped under `:root[data-pb-theme="wildfire"]`,
so it cannot touch PrintBee. `themes/wildfire.js` draws a small canvas of rising embers: pre-rendered sprites, capped
pixel ratio, paused while the tab is hidden or reduced motion is on, and the particle count halves itself if frames run
slow. Nothing from Wildfire stays in the page after switching away.

Palette: Obsidian `#100E0C`, Charcoal `#191511`, Forest Black `#111A14`, Deep Forest `#17442E`, Emerald `#236B46`,
Antique Gold `#C49A52`, Burnt Amber `#D68A32`, Ember `#F05A24`, Warm Ivory `#F2E9D9`. Fire Red `#A92B1E` is reserved for
danger states. Text and status colours were brightened where needed so every pairing passes 4.5:1 contrast
(`test_themes.py` checks this); dark ink sits on ember buttons because ivory on ember fails.

## Wildfire home page: same layout, different look

Wildfire never rearranges the PrintBee home page. The hero card, its text, "How it works", the prices and the footer
stay exactly where they are (checked to within 1-2 px). Only two things are swapped, each in its own spot, and
`destroy()` puts the originals back when the theme changes:

| File | Job |
| --- | --- |
| `themes/wildfire-home.js` | Replaces the printer picture in the hero, in the same box (the scene carries the picture's own class), with the 3D emblem and title; replaces each "How it works" icon with a 3D medallion (press, signpost, brass marker). No API calls. |
| `themes/wildfire-hero.js` | The Three.js scene: emblem behind, extruded PrintBee title in front (carved burnt-orange face, antique-gold bevels, dark outline plate), warm key light, orange rim, red fill, soft shadows, embers drawn from the ember model's pictures, a 5-stage reveal, pointer parallax on desktop. Transparent, so it floats on the card. Loaded only after the page is idle. |
| `themes/wildfire-title.js` | Letter outlines for the title (generated by `tools/make_wildfire_title.py` from the Lobster wordmark letters, SIL OFL). |
| `models/wildfire/emblem.glb`, `emblem-hq.glb` | Web copies of the supplied emblem. The light one (2048 px pictures, ~5 MB) shows first everywhere; capable screens then fetch the sharp one (4096 px pictures, 240k triangles, ~10 MB) quietly and swap it in. Rebuild with `python tools/make_wildfire_models.py "<folder with the originals>"`. The 60-70 MB originals are not in the repository. |
| `themes/img/*.webp` | The hero card still (fallback picture and gallery artwork), the ember atlas, and the three medallions. |

Quality ladder: weak devices (4 or fewer cores, 4 GB or less memory, Data Saver) skip the page-wide animation and the sharp
model; the hero lowers its own sharpness, shadows and embers if frames run slow. Reduced motion shows the final composition
without animation. If WebGL or the model is unavailable, the still picture stays. If any Wildfire file is missing on the
server, the engine falls back to PrintBee instead of showing half a theme.
To see the final composition at once while reviewing, call `document.querySelector("[data-wf-stage]").__wf.seek(99)`.

## Token reference (`--pb-*`)

`page` backdrop behind everything. `surface` / `surface-2` cards and subtle fills. `ink` / `muted` text.
`border` hairlines. `accent` the brand colour, `accent-strong` accent used as text on a surface, `accent-ink` text on
the accent. `success` `warning` `danger` `info` status colours. `radius-card` `radius-control` `radius-pill`
corners. `shadow-raised` `shadow-inset` `shadow-pressed` depth. `font-body` `font-display` typefaces.

## Writing theme-aware components

Use `var(--pb-*)` for every colour, radius, shadow and font in new CSS. Never write a literal colour in a component:
literal colours belong only inside a theme definition. Existing components already follow the active theme through the
bridge in `theme-engine.css` and the generated `theme-adapter.css`; if you change the dark-mode rules in
`customer-theme.css`, run `python tools/build_theme_adapter.py` (a test fails if you forget).

## JavaScript API

`window.PrintBeeThemes`: `list()`, `get(id)`, `current()`, `saved()`, `apply(id)`, `preview(id)`, `cancelPreview()`,
`commitPreview()`, `isPreviewing()`, `register(def)`, `validate(def)`, `onChange(fn)`. Listen with `onChange` to react
to a switch; do not read `localStorage` directly.

## Known limits of the foundation

Components that draw colour from images or hand-written gradients (for example the bee artwork and a few
illustrations) keep their PrintBee colours until a theme provides its own CSS in `/themes/<id>.css`. The default
PrintBee theme is untouched: with it active none of the bridge or adapter rules apply.
