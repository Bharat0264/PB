# PrintBee Theme Engine

A theme is a complete visual identity, not just light or dark. The engine lets the customer preview, apply and
keep a theme without reloading, and lets developers add a theme without touching existing pages.

Scope: the customer-facing pages (Home, Upload, Cart, Orders, Profile, Address, Help, Pricing, Terms, Change theme).
The warehouse, delivery and admin portals keep their own Sun Hive / Moon Hive styling for now.

## How it fits together

| File | Job |
| --- | --- |
| `theme-registry.js` | The list of themes. One object per theme. **The only file you edit to add a theme.** |
| `theme-engine.js` | The provider. Validates and registers themes, writes their tokens, applies one to `<html data-pb-theme="id">`, remembers the choice, previews and cancels. Loaded in `<head>` so there is no flash. |
| `theme-engine.css` | The semantic tokens (`--pb-*`) and the bridge from those tokens to the variables the existing stylesheets use. |
| `theme-adapter.css` | Generated by `tools/build_theme_adapter.py`. Makes the existing components follow any theme. Do not edit by hand. |
| `themes.html`, `themes.js`, `themes.css` | The Change theme gallery (`/themes`), reached from Profile > Appearance. |
| `/themes/<id>.css` | Optional extra CSS for a theme, loaded only while it is active. |

Mode: Sun Hive / Moon Hive (`data-theme` = `light` / `dark`) still works exactly as before and is independent of the
theme. A theme says which modes it supports. A theme with a single mode locks the page to it and hides the Sun/Moon
switch; switching to a theme that supports both restores the customer's own choice.

Persistence: the choice is saved in `localStorage` under `printbee-theme` and applied on every page before the first
paint. It is shared between tabs. An unknown or removed theme id falls back to PrintBee. Preview never saves anything.
Server-side persistence for signed-in customers is not built (it would need a profile API).

## Add a new theme

1. Open `theme-registry.js` and add an object to the `push(...)` call:

```js
{
  id: 'wildfire',                       // kebab-case, unique
  name: 'Wildfire',
  tagline: 'Short line',
  description: 'One or two sentences for the gallery card.',
  modes: ['dark'],                      // 'light', 'dark' or both
  preview: {dark: {page: '#120b08', surface: '#1f130d', ink: '#fff1e6', accent: '#ff6a1f'}},  // gallery thumbnail
  tokens: {
    dark: {                             // one set per supported mode; every token below is required
      page: '#120b08', surface: '#1f130d', 'surface-2': '#2a1a12',
      ink: '#fff1e6', muted: '#d1ad98', border: '#3a2418',
      accent: '#ff6a1f', 'accent-strong': '#ff9a5c', 'accent-ink': '#1a0a02',
      success: '#5fd08a', warning: '#ffb84d', danger: '#ff6b6b', info: '#6fb1ff',
      'radius-card': '14px', 'radius-control': '10px', 'radius-pill': '10px',
      'shadow-raised': '0 8px 22px rgb(0 0 0 / .45)',
      'shadow-inset': 'inset 0 1px 3px rgb(0 0 0 / .5)',
      'shadow-pressed': 'inset 0 2px 6px rgb(0 0 0 / .55)',
      'font-body': 'Manrope, system-ui, sans-serif', 'font-display': 'Manrope, system-ui, sans-serif',
    },
  },
  stylesheet: '/themes/wildfire.css',   // optional
}
```

2. If you set `stylesheet`, create `themes/wildfire.css`. Scope everything under `:root[data-pb-theme="wildfire"]`.
   Use it for what tokens cannot express: textures, gradients, illustrations, extra fonts (`@font-face`).
   The server serves `/themes/<name>.css|js|woff2` already.
3. Run `python -m unittest test_themes` to validate the definition. The engine also logs a clear console error and
   refuses to register an invalid theme, so a bad theme can never break a page.
4. Open `/themes`. The new card appears with Preview and Apply. Nothing else needs registering.

## Token reference (`--pb-*`)

`page` backdrop behind everything. `surface` / `surface-2` cards and subtle fills. `ink` / `muted` text.
`border` hairlines. `accent` the brand colour, `accent-strong` accent used as text on a surface, `accent-ink` text on
the accent. `success` `warning` `danger` `info` status colours. `radius-card` `radius-control` `radius-pill`
corners. `shadow-raised` `shadow-inset` `shadow-pressed` depth. `font-body` `font-display` typefaces.

## Writing theme-aware components

Use `var(--pb-*)` for every colour, radius, shadow and font in new CSS. Never write a literal colour in a component:
literal colours belong only inside a theme definition. Existing components already follow the active theme through the
bridge in `theme-engine.css` and the generated `theme-adapter.css`; if you change the dark-mode rules in
`customer-theme.css`, run `python tools/build_theme_adapter.py` (a test fails if you forget).

## JavaScript API

`window.PrintBeeThemes`: `list()`, `get(id)`, `current()`, `saved()`, `apply(id)`, `preview(id)`, `cancelPreview()`,
`commitPreview()`, `isPreviewing()`, `register(def)`, `validate(def)`, `onChange(fn)`. Listen with `onChange` to react
to a switch; do not read `localStorage` directly.

## Known limits of the foundation

Components that draw colour from images or hand-written gradients (for example the bee artwork and a few
illustrations) keep their PrintBee colours until a theme provides its own CSS in `/themes/<id>.css`. The default
PrintBee theme is untouched: with it active none of the bridge or adapter rules apply.
